# Milestone report: M2 Manifest ingestion and dependency analysis

## Summary
Milestone M2 implements end-to-end manifest ingestion, safe AST/regex-based dependency parsing, external package registry querying with bounded concurrency, deterministic upgrade classification, and an interactive developer console UI. The backend introduces `POST /api/manifest/analyze` (raw manifest payload) and `POST /api/manifest/upload` (multipart file upload), each strictly enforcing a 1 MB content/upload size limit with full route parity under `/api/v1/`. Ingestion safely supports Python `requirements.txt` (PEP 440/508, exact pins, non-pinned constraints, environment markers, inline comments, preserved pip directives and direct `@ url` references) and Node.js `package.json` (SemVer 2.0.0, runtime and devDependencies, scoped package escaping), while failing closed on unsupported specifiers (`workspace:`, `file:`, `link:`, `github:`, `npm:`) by preserving them with diagnostic explanations without external queries. External PyPI and npm clients enforce bounded streaming response limits (`MAX_RESPONSE_BYTES = 2MB`) without any unmetered fallback bypass, untrusted redirect SSRF destination controls, thread-local `requests.Session` management, and in-memory TTL caching with local catalog fallback. The frontend provides a high-density React 19 + TypeScript console with dual-mode input (raw editor with instant sample loaders and drag-and-drop file upload), summary metrics, status badges, filter chips, and an expandable dependency evaluation table.

## Changes
- `src/models/manifest.py`: Pydantic v2 domain schemas (`Ecosystem`, `DependencyType`, `DependencyStatus`, `RegistryLookupStatus`, `ParsedDependency`, `AnalyzedDependency`, `ManifestAnalysisRequest`, `ManifestAnalysisResponse`).
- `src/models/__init__.py`: Exported manifest data models.
- `src/analysis/semver_evaluator.py`: Pure-Python SemVer 2.0.0 parser and fail-closed range evaluator (`is_supported_semver_range`, `semver_satisfies`, `find_latest_compatible`, `find_latest_version`) handling caret (`^`), tilde (`~`), wildcards, relational bounds, hyphen ranges, and disjunctions; fails closed on unsupported schemes (`workspace:`, `file:`, `github:`, `npm:`) and malformed ranges.
- `src/analysis/manifest_parser.py`: Safe, zero-execution parsers for Python requirements and Node.js `package.json` with line preservation, PEP 508 direct reference detection (`req.url`), unsupported npm specifier detection, and diagnostic error containment.
- `src/services/registry_client.py`: Official PyPI JSON and npm registry HTTP clients with fixed official base URLs, untrusted redirect rejection (SSRF protection), bounded streaming chunk reading (`MAX_RESPONSE_BYTES = 2MB`) and `Content-Length` enforcement before JSON decoding without `.content` or `.json()` fallback bypass, thread-local `requests.Session` management (`ThreadLocalSessionFactory`) ensuring thread safety during concurrent lookups, thread-safe in-memory TTL caching with `threading.Lock()`, 8-second timeouts, scoped package encoding, yanked/deprecation detection, and local catalog fallback.
- `src/services/manifest_service.py`: Domain orchestration service coordinating parsing, bounded concurrent registry queries via `ThreadPoolExecutor(max_workers=8)`, stable result ordering strictly matching manifest input sequence, per-package error isolation, and classification into `UP_TO_DATE`, `UPGRADE_AVAILABLE`, and `PRESERVED`.
- `src/api/routes/manifest.py`: FastAPI endpoints for raw manifest analysis (`POST /manifest/analyze`) and multipart file upload (`POST /manifest/upload`), both enforcing a consistent 1 MB manifest size limit (`MAX_MANIFEST_SIZE_BYTES`) with HTTP 413 rejection, HTTP 422 diagnostic responses on malformed input, and non-blocking `asyncio.to_thread` execution.
- `src/api/main.py`: Mounted manifest routes under `/api` and `/api/v1`.
- `frontend/src/api/client.ts`: Extended TypeScript API client with `analyzeManifest` and `uploadManifest` functions and full domain interfaces.
- `frontend/src/components/ManifestAnalyzer.tsx`: High-density developer console component supporting raw editing, file drag-and-drop, sample loading, summary metrics, chip filtering, and expandable dependency details.

- `frontend/src/App.tsx` & `frontend/src/App.css`: Integrated `ManifestAnalyzer` with developer console design token styling.
- `tests/test_semver_evaluator.py`: 23 unit tests for SemVer parsing, precedence, range satisfaction, fail-closed validation on unsupported schemes (`workspace:`, `file:`, `github:`, `npm:`, malformed tags), and prerelease isolation.
- `tests/test_manifest_parser.py`: 12 unit tests for Python requirements and Node.js package.json parsing, error containment, directives preservation, PEP 508 direct references (`@ url`), and unsupported npm specifier preservation.
- `tests/test_registry_clients.py`: 20 unit tests verifying PyPI and npm queries, thread-safe TTL caching, scoped package URLs, yanked/deprecated detection, oversized response chunk capping, oversized `Content-Length` rejection, missing/misleading `Content-Length` safety, `iter_content` stream failure containment, rejection of unmetered fallback bypass, untrusted redirect SSRF rejection, safe redirect following, thread-local session isolation, and offline local catalog fallback.

- `tests/test_manifest_api.py`: 13 integration tests verifying FastAPI endpoints, multipart uploads, raw JSON analysis, exact 1MB boundary acceptance, raw and multipart oversized 1MB capping with HTTP 413, error diagnostics, and v1 route parity.

## Lens review
- **Architecture Lens:** Clean separation of concerns maintained across models (`src/models/manifest.py`), parsing (`src/analysis/`), external integrations (`src/services/registry_client.py`), application orchestration (`src/services/manifest_service.py`), and presentation (`src/api/routes/manifest.py`, `frontend/src/components/ManifestAnalyzer.tsx`).
- **Security Lens:** Enforced strict URL pinning to official registries to prevent SSRF (`https://pypi.org/pypi` and `https://registry.npmjs.org`), rejecting redirects to untrusted destinations before fetching. Streamed response limits (`MAX_RESPONSE_BYTES = 2MB`) are strictly enforced without unmetered fallback bypasses. Implemented consistent 1MB size caps on both raw and multipart paths. Safe zero-execution AST/regex parsing prevents host execution. Secret scanner confirms zero credentials introduced across all new code.
- **QA / Testing Lens:** 72 new backend unit and integration tests and 6 frontend tests added. Full regression suite is 100% green (326 passing tests, 0 regressions).
- **UX / Accessibility Lens:** Followed `.agents/skills/frontend-design/SKILL.md` developer tooling standards. High-density console layout with distinctive dark slate palette, clear contrast, keyboard-accessible tabs and buttons, semantic status badges, and expandable row details.
- **SRE / Performance Lens:** Bounded concurrency (`max_workers=8`) executes independent registry queries concurrently without overwhelming registries or thread limits. `ThreadLocalSessionFactory` provisions per-thread sessions avoiding shared mutable session contention while preserving HTTP connection pooling within threads. Streaming response capping (`MAX_RESPONSE_BYTES = 2MB`) prevents unbounded memory consumption. Thread-safe in-memory TTL caching eliminates redundant HTTP calls. Safe fallback to local catalog guarantees resilience during network disconnects.

## Known limitations
- PyPI and npm public queries require network access; when completely offline and a package is not present in the local catalog fallback (`src/data/package_catalog.json`), status is safely marked `PRESERVED` with a `NETWORK_ERROR` diagnostic notice.
- npm ranges with complex git URL dependencies or custom registry tags beyond `latest` are classified as `PRESERVED` (fail-closed).
- PEP 508 direct references (`pkg @ url`) are preserved as non-evaluable for registry upgrades and not queried against PyPI.
