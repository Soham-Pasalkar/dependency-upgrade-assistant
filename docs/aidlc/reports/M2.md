# Milestone report: M2 Manifest ingestion and dependency analysis

## Summary
Milestone M2 implements end-to-end manifest ingestion, safe AST/regex-based dependency parsing, external package registry querying, deterministic upgrade classification, and an interactive developer console UI. The backend introduces `POST /api/manifest/analyze` (raw manifest payload) and `POST /api/manifest/upload` (multipart file upload capped at 1MB), with full route parity under `/api/v1/`. Ingestion supports Python `requirements.txt` (PEP 440/508, exact pins, non-pinned constraints, environment markers, inline comments, preserved pip directives and URLs) and Node.js `package.json` (SemVer 2.0.0, runtime and devDependencies, scoped package escaping), with fixed official PyPI and npm endpoints, in-memory TTL caching, and zero host code execution. The frontend provides a high-density React 19 + TypeScript console with dual-mode input (raw editor with instant sample loaders and drag-and-drop file upload), summary metrics, status badges, filter chips, and an expandable dependency evaluation table.

## Changes
- `src/models/manifest.py`: Pydantic v2 domain schemas (`Ecosystem`, `DependencyType`, `DependencyStatus`, `RegistryLookupStatus`, `ParsedDependency`, `AnalyzedDependency`, `ManifestAnalysisRequest`, `ManifestAnalysisResponse`).
- `src/models/__init__.py`: Exported manifest data models.
- `src/analysis/semver_evaluator.py`: Pure-Python SemVer 2.0.0 parser and range evaluator handling caret (`^`), tilde (`~`), wildcards, relational bounds, hyphen ranges, and disjunctions without spawning Node.js subprocesses.
- `src/analysis/manifest_parser.py`: Safe, zero-execution parsers for Python requirements and Node.js `package.json` with line preservation and diagnostic error containment.
- `src/services/registry_client.py`: Official PyPI JSON and npm registry HTTP clients with fixed URLs (anti-SSRF), in-memory TTL caching, 8-second timeouts, scoped package encoding, yanked/deprecation detection, and local catalog fallback.
- `src/services/manifest_service.py`: Domain orchestration service coordinating parsing, concurrent registry queries, version evaluation, and classification into `UP_TO_DATE`, `UPGRADE_AVAILABLE`, and `PRESERVED`.
- `src/api/routes/manifest.py`: FastAPI endpoints for raw manifest analysis (`POST /manifest/analyze`) and multipart file upload (`POST /manifest/upload`) with 1MB size enforcement and 422 diagnostic responses.
- `src/api/main.py`: Mounted manifest routes under `/api` and `/api/v1`.
- `frontend/src/api/client.ts`: Extended TypeScript API client with `analyzeManifest` and `uploadManifest` functions and full domain interfaces.
- `frontend/src/components/ManifestAnalyzer.tsx`: High-density developer console component supporting raw editing, file drag-and-drop, sample loading, summary metrics, chip filtering, and expandable dependency details.
- `frontend/src/components/ManifestAnalyzer.test.tsx`: 6 Vitest unit tests covering tabs, samples, analysis flow, filtering, and error diagnostics.
- `frontend/src/App.tsx` & `frontend/src/App.css`: Integrated `ManifestAnalyzer` with developer console design token styling.
- `tests/test_semver_evaluator.py`: 8 unit tests for SemVer parsing, precedence, range satisfaction, and latest version identification.
- `tests/test_manifest_parser.py`: 9 unit tests for Python requirements and Node.js package.json parsing, error containment, and directives preservation.
- `tests/test_registry_clients.py`: 10 unit tests verifying PyPI and npm queries, TTL caching, scoped package URLs, yanked/deprecated detection, and offline local catalog fallback.
- `tests/test_manifest_service.py`: 2 integration tests verifying classification, summary counts, and diagnostics.
- `tests/test_manifest_api.py`: 11 integration tests verifying FastAPI endpoints, multipart uploads, size capping, error diagnostics, and v1 route parity.

## Lens review
- **Architecture Lens:** Clean separation of concerns maintained across models (`src/models/manifest.py`), parsing (`src/analysis/`), external integrations (`src/services/registry_client.py`), application orchestration (`src/services/manifest_service.py`), and presentation (`src/api/routes/manifest.py`, `frontend/src/components/ManifestAnalyzer.tsx`).
- **Security Lens:** Enforced strict URL pinning to official registries to prevent SSRF (`https://pypi.org/pypi` and `https://registry.npmjs.org`). Implemented 1MB upload file caps and zero host code execution during manifest ingestion. Secret scanner confirms zero credentials introduced.
- **QA / Testing Lens:** 40 new backend unit and integration tests and 6 frontend tests added. Full regression suite is 100% green (294 passing tests).
- **UX / Accessibility Lens:** Followed `.agents/skills/frontend-design/SKILL.md` developer tooling standards. High-density console layout with distinctive dark slate palette, clear contrast, keyboard-accessible tabs and buttons, semantic status badges, and expandable row details.
- **SRE / Performance Lens:** In-memory TTL caching eliminates redundant HTTP calls. Timeouts are set to 8 seconds. Safe fallback to local catalog guarantees resilience during network disconnects.

## Known limitations
- PyPI and npm public queries require network access; when completely offline and a package is not present in the local catalog fallback (`src/data/package_catalog.json`), status is safely marked `PRESERVED` with a `NETWORK_ERROR` diagnostic notice.
- npm ranges with complex git URL dependencies or custom registry tags beyond `latest` are classified as `PRESERVED`.

- None. Implementation strictly conforms to the approved G3 milestone plan and architectural specifications.
