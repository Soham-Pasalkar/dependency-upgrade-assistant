# Milestone report: M5 Sandboxed validation

## Summary
Milestone M5 delivers the sandboxed validation subsystem for executing dependency verification, syntax compilation, and test execution inside isolated, hardened Docker containers. The engine enforces non-root execution (`1000:1000`), total capability dropping (`--cap-drop=ALL`), privilege escalation prevention (`no-new-privileges`), default network isolation (`--network none`), strict resource ceilings (512MB RAM, 1.0 CPU, 64 PIDs), read-only root filesystems, and temporary memory mounts. An ephemeral workspace snapshot manager replicates repository manifests while scrubbing secrets, `.env` files, and credentials, rejecting external symlink escapes. Crucially, the system implements a fail-closed policy that truthfully reports `NOT_RUNNABLE` when the Docker daemon is absent or unreachable, strictly preventing untrusted code from ever running directly on the host machine.

## Lens review
- **Architecture Lens:** Provider-independent `SandboxRunnerInterface` cleanly decouples execution logic from Docker daemon mechanics, enabling graceful degradation to `NOT_RUNNABLE` without blocking the developer workflow.
- **Security Lens:** Untrusted code execution is strictly prohibited on the host; container isolation enforces dropped capabilities, non-root user, `--network none`, and secret scrubbing from snapshots.
- **QA Lens:** 21 new backend tests and 4 new frontend tests added, bringing total test coverage to 484 backend and 17 frontend tests with 100% green pass rate.
- **UX Lens:** The developer interface clearly visualizes Docker engine availability, containment specifications, command breakdown, and an expandable terminal console.
- **SRE Lens:** Resource ceilings (512MB RAM, 1.0 CPU, 64 PIDs) and a 512KB bounded log buffer protect server memory and compute against fork-bombs and runaway stdout loops.

## Known limitations
- When the Docker daemon is offline or absent on the host workstation (e.g. macOS developer machine without Docker Desktop running), the probe accurately reports `NOT_RUNNABLE` and tests are not executed. Live container execution requires a running Docker daemon.
- Single-tenant trust boundary: Protection against local symlink-swap race conditions (TOCTOU) relies on filesystem containment and permissions rather than kernel-level `openat(O_NOFOLLOW)` descriptor trees.

## Deviations
- None. Implementation strictly adheres to approved G3 milestone plan and M5 autonomous engineering execution directive.
