# Milestone report: M9 Premium frontend redesign and existing workflow integration

## Summary
The React frontend was redesigned as a product experience. It now opens on a landing page: framed navigation, an editorial hero, a product readout built from real interface parts, and sections on the workflow, evidence and isolation. A hash route leads into a seven-stage analyzer: Manifest, Dependency health, Recommendations, Plan and diff, Approval, Validation, Export. A progress rail tracks the stages, and every stage calls the existing APIs. Internal development content was removed from the UI and from backend user-facing strings. Recommendations now label how each version was established. Validation and export are disabled in the UI until the plan is approved. Server-side enforcement of approval is scheduled for M10.

- `frontend/index.html`, `public/favicon.svg`: product title, description, fonts (Geist, Geist Mono from Google Fonts) and a new mark. The unused template assets `src/assets/react.svg` and `vite.svg` were removed.

- Backend user-facing wording, with no behaviour change:
  - `src/services/ai/deterministic_engine.py` (3 strings)
  - `src/services/ai/validator.py` (1 string)
  - `src/services/upgrade_planner.py` (1 string)
- Tests:

  - 2 backend assertions were updated to the new wording.

## Lens review
- **UX:** The screenshot review found these defects, all fixed:
  - The headline wrapped to four lines.
  - The hero had dead space above the headline.
  - Readout rows wrapped.
  - Orange was overused on candidates and actions.
  - Raw backend summaries were shown ("[Offline Fallback Active]", "Integrity check: PASSED").
  - The download block was muddy.
  - On mobile, tables pushed status and basis columns off-screen.
- **Accessibility:**
  - The headline's line spans had no spaces between them, so screen readers read "Dependencyupgrades". Found by a test and fixed.
  - The tab pattern now uses `aria-selected`, and the rail uses `aria-current="step"` with text for each state.
  - Focus moves to a stage's heading when that stage opens.
  - The light layer behind the hero caused 104 px of horizontal overflow during keyboard navigation. Fixed.
- **Security:** No new data flows. The Google Fonts request is the only new outbound call, made by the browser. Validation and export are blocked in the UI until approval, but the backend does not enforce this yet (M10, FR-16).
- **Honesty:**
  - When Docker is unavailable, validation shows "Not runnable" and says nothing was executed. It never shows a pass.
  - A pass from syntax-only checks is labelled as such.
  - Model suggestions are labelled distinctly from registry and rule results.

## Known limitations
- **Approval is client-side only.** It is enforced in the UI but not yet by the server. `/api/validation/execute` and `/api/export` still accept unapproved proposals. This is M10 scope (FR-15/FR-16).
- **No repository URL entry.** The analyzer is manifest-first (paste or upload). GitHub analysis lands in M10, so the CTA reads "Analyze dependencies", not "Analyze a repository".
- **Validation remains syntax-level** where it runs. The workspace and offline staging come in M10. Live Docker was not exercised locally because Docker is not installed. The browser run showed the Not runnable path only.
- **Not verified:** live Ollama, so the model-suggestion UI path is covered by component tests only. A formal WCAG contrast audit was not done, though token contrast was checked by calculation: text-2 is about 7.8:1 and the accent about 5.9:1 on the background. No screen-reader session was run.
- **Fonts load from Google Fonts.** Offline use falls back to system fonts.
- **One lint warning remains:** react set-state-in-effect in `BackendStatus`, on the async health probe.

## Deviations
- **Backend files changed in a frontend milestone.** Five user-facing backend strings mentioned internal milestones ("in M4", "M3 candidate"). They were reworded to satisfy FR-21. Two existing backend assertions checked that wording:
  - `tests/test_deterministic_fallback.py:217`
  - `tests/test_ground_truth_validator.py:353`

  Each now asserts the new sentence. They still verify that the pin-update note is present, so no behaviour assertion was weakened. NFR-7R permits this; it is recorded here.
- **Component tests were rewritten for the new copy and markup.** Behaviour assertions were kept, and approval-gating assertions were added.
- **Note N6 was recorded during M9.** The v2.0 completion report wrongly claimed that the Origin, Content-Type and `X-DUA-Client` checks existed. They will be implemented in M10 alongside Host-header validation.
