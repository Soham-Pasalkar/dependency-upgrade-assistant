# Milestone report: M3 Upgrade recommendations and AI provider

## Summary
Milestone M3 establishes the intelligent upgrade recommendation subsystem for Dependency Upgrade Assistant 2.0. It defines a provider-independent AI recommendation interface alongside a local Ollama client implementation supporting dynamic model discovery without hardcoded model assumptions. In accordance with core security and correctness principles, candidate versions suggested by AI are strictly validated against external registry ground truth (PyPI and npm), automatically rejecting and reverting any hallucinated releases. When the local Ollama runtime is unreachable or offline, the subsystem seamlessly activates an automated deterministic semantic versioning engine with zero user disruption.

## Changes
- `src/models/recommendation.py`: Pydantic v2 domain models for recommendation categories (`RECOMMENDED`, `CAUTION`, `NO_UPGRADE_NEEDED`, `PRESERVED_UNSUPPORTED`), action priorities (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), ground-truth validation statuses, dynamic model metadata, and batch request/response payloads.
- `src/models/__init__.py`: Re-exported all M3 recommendation models.
- `src/services/ai/base.py`: Provider-independent abstract base class `AIRecommendationProvider` and custom exception hierarchy (`AIProviderUnavailableError`, `AIModelNotFoundError`, `AIInferenceTimeoutError`, `AIResponseParseError`).
- `src/services/ai/ollama_provider.py`: Local Ollama provider implementing dynamic model discovery via `/api/tags`, safe prompt construction transmitting strictly public registry metadata (never repository secrets or private source code), and structured JSON schema enforcement.
- `src/services/ai/deterministic_engine.py`: Zero-hallucination, rule-based SemVer 2.0.0 and PEP 440 upgrade recommendation engine for offline and fallback operation.
- `src/services/ai/validator.py`: `RegistryGroundTruthValidator` for deterministic cross-referencing of proposed versions against registry available releases, rejecting hallucinations and tagging with `REJECTED_HALLUCINATION`.
- `src/services/recommendation_service.py`: Coordinator service managing provider selection, offline fallback detection, batch ground-truth validation, and metrics calculation.
- `src/api/routes/recommendations.py`: FastAPI endpoints for `GET /api/ai/status` (and `/api/v1/ai/status`, alias `/api/recommendations/status`) and `POST /api/recommendations/generate` (and `/api/v1/recommendations/generate`).
- `src/api/main.py`: Mounted recommendations router under `/api` and `/api/v1`.
- `frontend/src/api/client.ts`: TypeScript interfaces and API client functions `getAiStatus()` and `generateRecommendations()`.
- `frontend/src/components/ManifestAnalyzer.tsx`: React UI integrating AI status indicator, model selector, force-deterministic toggle, recommendation generation button, summary tags, and structured recommendations table.
- `frontend/src/App.css`: Developer console design tokens and high-density styling for recommendations UI, badges, and fallback indicators.
- `tests/test_ai_provider.py`: Conformance tests for abstract provider interface and exception hierarchy (4 tests).
- `tests/test_ollama_provider.py`: Unit tests for OllamaProvider with mock client covering availability, dynamic model discovery, model selection, prompt construction, and error mapping (10 tests).
- `tests/test_deterministic_fallback.py`: Unit tests for deterministic SemVer fallback across major, minor, patch, deprecated, and preserved dependencies (8 tests).
- `tests/test_ground_truth_validator.py`: Unit tests verifying acceptance of valid candidate versions and strict rejection of AI hallucinations (4 tests).
- `tests/test_recommendations_api.py`: FastAPI TestClient integration tests covering online, offline fallback, and force-deterministic endpoints (5 tests).
- `frontend/src/components/ManifestAnalyzer.test.tsx`: Vitest component tests verifying AI status, recommendation rendering, badges, and fallback handling (8 tests).

## Lens review
- **Architecture Lens:** Verified complete separation between AI recommendation coordinator (`RecommendationService`), provider abstractions (`AIRecommendationProvider`), deterministic solver (`DeterministicRecommendationEngine`), and ground-truth validation (`RegistryGroundTruthValidator`). Swapping provider implementations does not affect API contracts or frontend clients.
- **Security Lens:** Strictly validated that no private repository source code, AST dumps, or credentials are included in prompts to Ollama. Prompts contain exclusively public package names, version strings, constraints, and public registry version lists. Secret scanner verified zero credentials across all new files.
- **QA Lens:** Added 31 new backend tests and 2 new frontend Vitest tests covering edge cases: offline daemon, non-existent models, timeouts, malformed JSON, major/minor/patch SemVer jumps, yanked/deprecated packages, and hallucinated candidate versions. Full suite passed 100% green (357 Python tests, 13 frontend tests).
- **UX Lens:** Implemented responsive developer console UI with clear status indicators for Ollama online vs offline fallback, semantic priority badges (Critical, High, Medium, Low), category tags, registry verification badges, and expandable risk assessment details.
- **SRE Lens:** All network calls to local Ollama runtime feature explicit bounded timeouts (default 30s) and exception handling, preventing server thread lockups or hanging worker processes.

## Known limitations
- Local Ollama daemon must be installed and running on `http://127.0.0.1:11434` with at least one model pulled to generate LLM-based recommendations; otherwise, the subsystem gracefully falls back to the deterministic SemVer engine.
- Multi-package cross-dependency constraint solving (e.g. resolving transitive diamond dependency conflicts) is scheduled for subsequent milestones.

## Deviations
- None. Implementation strictly adheres to approved G3 milestone plan and M3 acceptance criteria.
