# Milestone report: M3 Upgrade recommendations and AI provider

## Summary
Milestone M3 establishes the intelligent upgrade recommendation subsystem for Dependency Upgrade Assistant 2.0. It defines a provider-independent AI recommendation interface alongside a local Ollama client implementation supporting dynamic model discovery without hardcoded model assumptions. In accordance with core security and correctness principles, candidate versions suggested by AI are strictly validated against external registry ground truth (PyPI and npm), automatically rejecting and reverting any hallucinated or incompatible releases. When the local Ollama runtime is unreachable or offline, the subsystem seamlessly activates an automated deterministic semantic versioning engine with zero user disruption. Following independent code review, an engineering rework addressed constraint compatibility enforcement, conservative deterministic fallback, threadpool concurrency, Ollama endpoint security, and untrusted AI output handling.

## Changes
- `src/models/recommendation.py`: Pydantic v2 domain models for recommendation categories (`RECOMMENDED`, `CAUTION`, `NO_UPGRADE_NEEDED`, `PRESERVED_UNSUPPORTED`), action priorities (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), ground-truth validation statuses (`VALIDATED`, `REJECTED_HALLUCINATION`, `REJECTED_INCOMPATIBLE`, `FALLBACK_DETERMINISTIC`, `SKIPPED`), dynamic model metadata, and batch request/response payloads.
- `src/models/__init__.py`: Re-exported all M3 recommendation models.
- `src/api/config.py`: Added `ALLOW_REMOTE_OLLAMA: bool = Field(default=False)` configuration flag for explicit authorization of remote Ollama daemons.
- `src/services/ai/base.py`: Provider-independent abstract base class `AIRecommendationProvider` and custom exception hierarchy (`AIProviderUnavailableError`, `AIModelNotFoundError`, `AIInferenceTimeoutError`, `AIResponseParseError`).
- `src/services/ollama_client.py`: Enhanced with `validate_and_sanitize_ollama_endpoint` enforcing loopback access by default (`127.0.0.1`, `localhost`, `::1`), rejecting embedded credentials, disallowing redirects (`allow_redirects=False`), raising `OllamaSecurityError` on 3xx redirect responses, and normalizing URLs.
- `src/services/ai/ollama_provider.py`: Local Ollama provider implementing dynamic model discovery via `/api/tags`, safe prompt construction transmitting strictly public registry metadata (never repository secrets or private source code), untrusted AI output validation (dropping unknown packages, ignoring duplicates, bounding candidate version strings to $\le 64$ characters, bounding text fields to $\le 500$ characters, and applying safe enum fallbacks).
- `src/services/ai/deterministic_engine.py`: Conservative, zero-hallucination rule-based SemVer 2.0.0 and PEP 440 upgrade recommendation engine for offline and fallback operation. For range constraints, strictly prefers `latest_compatible_version` and never substitutes `latest_version` blindly; returns safe no-upgrade with clear diagnostic if no compatible candidate exists. For exact pins, classifies bumps under `CAUTION` with M4 manifest update notices. Enforces downgrade prevention and stable-to-prerelease blocking.
- `src/services/ai/validator.py`: `RegistryGroundTruthValidator` cross-referencing proposed versions against registry available releases and declared constraints. Flags hallucinations as `REJECTED_HALLUCINATION`, flags constraint violations and downgrades as `REJECTED_INCOMPATIBLE`, accepts exact pin bumps under `CAUTION`, and applies fail-closed fallback to verified compatible M2 versions or safe no-upgrade.
- `src/services/recommendation_service.py`: Coordinator service managing provider selection, offline fallback detection, batch ground-truth validation, URL sanitization in status responses, and metrics calculation.
- `src/api/routes/recommendations.py`: FastAPI endpoints for `GET /api/ai/status` (and `/api/v1/ai/status`, alias `/api/recommendations/status`) and `POST /api/recommendations/generate` (and `/api/v1/recommendations/generate`) utilizing `run_in_threadpool` from `starlette.concurrency` to prevent blocking the event loop.
- `src/api/main.py`: Mounted recommendations router under `/api` and `/api/v1`.
- `frontend/src/api/client.ts`: TypeScript interfaces and API client functions `getAiStatus()` and `generateRecommendations()`, including `REJECTED_INCOMPATIBLE` validation status.
- `frontend/src/components/ManifestAnalyzer.tsx`: React UI integrating AI status indicator, model selector, force-deterministic toggle, recommendation generation button, summary tags, structured recommendations table, and `⚠ Incompatible` badge rendering.
- `frontend/src/App.css`: Developer console design tokens and high-density styling for recommendations UI, badges, and fallback indicators.
- `tests/test_ai_provider.py`: Conformance tests for abstract provider interface and exception hierarchy (4 tests).
- `tests/test_ollama_client.py`: Comprehensive tests for Ollama client, health checking, dynamic model discovery, endpoint security, credential rejection, remote host authorization, and redirect blocking (30 tests).
- `tests/test_ollama_provider.py`: Unit tests for OllamaProvider with mock client covering availability, dynamic model discovery, model selection, prompt construction, error mapping, and untrusted output validation (11 tests).
- `tests/test_deterministic_fallback.py`: Unit tests for deterministic SemVer fallback across major, minor, patch, deprecated, range-constrained, and exact pin dependencies (11 tests).
- `tests/test_ground_truth_validator.py`: Unit tests covering all 13 validation scenarios including PEP 440/SemVer compatibility, exact pin bumps, range violations, hallucinations, downgrades, prereleases, fail-closed fallback, and unknown package rejection (11 tests).
- `tests/test_recommendations_api.py`: FastAPI integration tests covering online, offline fallback, force-deterministic endpoints, route parity on `/api/` and `/api/v1/`, and non-blocking threadpool concurrency (6 tests).
- `frontend/src/components/ManifestAnalyzer.test.tsx`: Vitest component tests verifying AI status, recommendation rendering, badges, and fallback handling (8 tests).

## Lens review
- **Architecture Lens:** Complete separation between AI recommendation coordinator (`RecommendationService`), provider abstractions (`AIRecommendationProvider`), deterministic solver (`DeterministicRecommendationEngine`), and ground-truth validation (`RegistryGroundTruthValidator`). Swapping provider implementations does not affect API contracts or frontend clients. Synchronous compute operations are routed through `run_in_threadpool`.
- **Security Lens:** Strictly validated that no private repository source code, AST dumps, or credentials are included in prompts to Ollama. Prompts contain exclusively public package names, version strings, constraints, and public registry version lists. Endpoint security enforces local loopback by default, rejects embedded URL credentials, disallows redirects (`allow_redirects=False` with `OllamaSecurityError`), and sanitizes status endpoint URLs. Secret scanner verified zero credentials across all new files.
- **QA Lens:** Added 51 new backend tests and updated frontend Vitest tests covering edge cases: offline daemon, non-existent models, timeouts, malformed JSON, major/minor/patch SemVer jumps, yanked/deprecated packages, hallucinated candidate versions, range constraint violations, downgrade prevention, prerelease policy, and concurrent requests. Full suite passed 100% green (377 Python tests, 13 frontend tests).
- **UX Lens:** Implemented responsive developer console UI with clear status indicators for Ollama online vs offline fallback, semantic priority badges (Critical, High, Medium, Low), category tags, registry verification badges (`✓ Validated`, `⚠ Reverted`, `⚠ Incompatible`, `Rules`, `—`), and expandable risk assessment details.
- **SRE Lens:** All network calls to local Ollama runtime feature explicit bounded timeouts (default 30s) and exception handling, preventing server thread lockups or hanging worker processes. Threadpool execution ensures async event loop responsiveness during heavy inference or fallback calculations.

## Known limitations
- Local Ollama daemon must be installed and running on `http://127.0.0.1:11434` with at least one model pulled to generate LLM-based recommendations; otherwise, the subsystem gracefully falls back to the deterministic SemVer engine.
- Multi-package cross-dependency constraint solving (e.g. resolving transitive diamond dependency conflicts) is scheduled for subsequent milestones.

## Deviations
- None. Implementation strictly adheres to approved G3 milestone plan and M3 acceptance criteria.
