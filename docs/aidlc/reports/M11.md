# Milestone report: M11 Backend security and reliability stabilization

## Summary
M11 closes the open findings from the post-M10 backend audit. It also re-verifies the earlier post-M10 fixes F1–F7, which are recorded in note N8 and are still uncommitted.

- **F13, approval integrity:** the validation operation is now server-controlled and bound into the approval. Previously a client could substitute a no-op test command after approval, and validation and export then reported PASSED.
- **F10, data provenance:** offline-catalog data is explicitly labelled and never planned.
- **F8 and F9, retention:** exports and persisted runs are cleaned up on a bounded schedule.
- **F11 and F12:** documented, with the M12 direction.

Criterion 7, which needs CI with Docker on the M11 commit, is pending the owner's authorization to commit and push.

## Lens review
- **Security:**
  - The validation operation can no longer be chosen by the client. The policy fingerprint is checked at validation, apply and export, and approvals from before M11 fail closed.
  - Offline data cannot become a patch.
  - Retention deletes only export-ID-shaped directories and expired runs. It never follows symlinks and never removes work whose plan is still valid.
- **API:** the contract changes are deliberate and documented in architecture.md Revision 3.
  - Clients sending the old default limits still work.
  - Clients sending `custom_test_cmd` or `image_override` now get 422.
- **Operations:** retention adds no background framework. It runs at startup and at most every 15 minutes on writes.
- **UX:** no redesign. The validation request is simplified, and the labels "Offline data, unverified" and "offline data" now come from API fields.

## Known limitations
- **Docker not verified for M11.** Docker integration tests have not run on M11 code; that needs CI after a push.
- **F11:** analysis and validation are still synchronous; cancellation is ineffective in practice. M12 should introduce job-style execution, see architecture.md Revision 3.
- **F12:** DNS time-of-check vs time-of-use residual, and the unauthenticated GitHub rate limit of 60/h, are documented and not changed.
- **Shared export directory.** The exporter still defaults to the system temp directory, which the test suite shares with real use: 333 directories had accumulated before M11. Retention now bounds this. A dedicated configurable export directory is a candidate follow-up.
- **No staged run.** The F13 validation path was exercised locally only with a mocked container runner, and live only as Not runnable.
- **Out of scope here:** live Ollama is unverified; `pip-audit` is not installed; one frontend lint warning remains; the branch is unprotected.

## Deviations
- **Validation tests:**
  - `tests/test_validation_api.py`: the attacker-image test now expects 422 for any `image_override`, including allowlisted images. This is stricter than the previous 400 for non-allowlisted images only.
  - The success test no longer sends a 30 s timeout, which the server policy now owns.
- **`tests/test_export_api.py`:** the registered execution fixture records the policy fingerprint, as a real server-run validation would.
- **`tests/approval_helpers.py`:** records the server-derived policy fingerprint, mirroring `POST /approve`.
- **`tests/test_runs_api.py`:** the fake service accepts the new `policy` argument.
- **`tests/test_registry_clients.py`:** the catalog-fallback test now asserts `OFFLINE_CATALOG` instead of `SUCCESS`. This is the approved F10 API change.
- **`tests/test_docker_staging_integration.py`:** no longer passes a timeout; the server policy sets it.
- **Process:** no test was removed. The `.aidlc` history (M10 approval, N8, replan, G3 approval) is preserved.
